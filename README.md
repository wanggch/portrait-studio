# 人像工坊 · Portrait Studio

本地优先的 3D 人像创作配置台。只选择需要的参数，也可以只选大类；未选内容不会进入复制结果。

产品目标与验收基线：[需求文档](docs/需求文档.md)。

## 启动

macOS 可双击 **`start.command`**，随后打开 **http://127.0.0.1:5173**。保持终端窗口打开，按 Control+C 停止服务。脚本优先使用本机 nvm 中的 Node.js LTS，不修改系统配置。

或使用 Node.js 22 / 24 LTS：

```bash
cd portrait-studio
npm ci
npm run dev
```

当前机器系统默认 Node.js 有动态库缺失，已发现可用的 nvm Node.js 22；启动脚本已兼容这一环境。依赖已安装，首次在其他设备安装依赖需要联网，运行不需要远程模型、字体或图片服务。

生产预览：`npm run build` 后运行 `npm run preview -- --port 5173`。**使用相同浏览器、相同地址和端口**，才能访问同一份本地历史。`localhost` 与 `127.0.0.1` 的存储不通用。

## 使用

1. 左侧选择人物、服饰、饰品道具、姿势、场景、摄影、光线风格或故事。各组均可跳过。
2. 大类可以直接选择；展开字段和默认 3D 外观不代表已选。字段支持自定义、清除、锁定和主动授权下游补全。
3. 中间自由旋转、缩放、平移检查模特。拍摄视角独立保存；只有点击“设为拍摄机位”才将当前观察机位加入参数。
4. 右侧检查已选参数，选择简报或 JSON，一键复制。复制成功后自动建立历史记录。
5. 历史中可收藏、搜索、比较、再次复制原文、从快照新建副本。默认不会覆盖当前编辑。
6. 顶栏保存命名方案；模板库可保存当前整套或某个模块。模板、随机方案先预览差异再应用。
7. 定期在“设置与备份”中导出全部本地数据。清理浏览器数据可能导致 IndexedDB 内容丢失。

## 已实现

- 八组可选参数、级联子项、自定义值、多选、色板、锁定、搜索。
- 纯已选内容的创作简报 / JSON、Markdown 下载、剪贴板失败后的手动复制。
- 程序化成年女性风格模型；有限服装、发型、饰品、姿态和简化场景预览。
- 自由观察与拍摄视角分离；画幅、焦段、构图、灯光设置与取景截图。
- 命名方案、草稿自动保存、复制历史、手动版本、自动恢复检查点；收藏与筛选。
- 撤销重做、方案差异对比、自定义模板、受约束随机、冲突提示。
- IndexedDB 持久化、JSON 导入与全量备份恢复、结构及数值校验。
- WebGL 不可用时保留表单与复制；本地服务只绑定回环地址。

## 当前模型的边界

**这是可运行的程序化造型参考，不是已采购并适配完毕的高质量数字人资产库。**

服装与发型采用原创几何变体；部分款式只有轮廓差异，细腻面料、精细五官、表情、妆容等只导出。衣料不做物理模拟，坐卧和复杂姿势可能出现局部穿插。自定义款式仍会保留为创作意图，但不能声称对应 3D 准确还原。

需求文档中的资产数量为待确认建议，不是本项目已完成高保真资产采购的承诺。完整能力、差距和资产说明见 [实现状态](docs/实现状态.md) 与 [资产说明](docs/资产说明.md)。不对接任何现有 Skill，不调用 Agent 或生图服务。

## 开发与验证

```bash
npm test
npm run test:e2e
npm run build
```

端到端测试使用本机 Google Chrome；其他设备可修改 `playwright.config.ts` 使用已安装的浏览器。测试会自动启停开发服务器，使用隔离的浏览器存储，不改动个人历史。

```text
src/catalog.ts       参数目录与预设
src/domain.ts        稀疏导出、校验、冲突、锁定、模板与历史规则
src/storage.ts       IndexedDB 与下载
src/Studio.tsx       原创程序化人物、环境与独立摄影机
src/App.tsx          编辑器、历史、方案、模板与设置
src/styles.css       页面样式
tests/               单元与浏览器回归测试
```

未来本地 Agent 通过独立适配器消费稀疏参数，无需把 Agent 协议写进界面字段。数据说明见 [参数协议](docs/参数协议.md)。
